Lesson 06: Bevy UI Flexbox Layout & Live Countdown HUD

Players shouldn't have to guess whether 2 seconds or 8 seconds remain before elimination! In this lesson, you will build a crisp top-of-screen HUD bar using Bevy 0.20's Flexbox Node layout and children![] hierarchy macro to display the live 10s / 5s countdown and survivor count.

UI Layout Concepts

  • Screen-space UI coordinates vs. 2D world space
  • Flexbox containers (justify_content, align_items, column_gap)
  • Pass-through overlays via Pickable::IGNORE

Bevy 0.20 Concepts

  • Node (including border_radius), BackgroundColor & BorderColor::all
  • Text::new(...), TextFont::from_font_size(...) & TextColor
  • Spawning declarative parent-child trees with children![]

Rust Concepts

  • Declarative macros (children![...] & format!(...))
  • Format specifiers like {:.1} (1 decimal place)
  • Disjoint marker queries (With<T>, Without<U>) for dynamic UI text

1. How Bevy UI Renders Over Your 2D World

Unlike Sprite entities—which live in center-origin world coordinates and move if the camera moves—Node entities live in a dedicated screen-space UI layout pass powered by the CSS Flexbox & Grid algorithms (via the taffy layout engine):

  • PositionType::Absolute with top: Val::Px(10.0), left: Val::Px(0.0), and width: Val::Percent(100.0) pins a full-width invisible flex row across the top margin of the window—sitting cleanly above your centered 800 × 560 arena!
  • Setting justify_content: JustifyContent::Center centers the inner pill badge horizontally regardless of window size.
  • Adding Pickable::IGNORE on decorative HUD containers tells Bevy's pointer picking system not to swallow mouse clicks—a great habit before we add clickable menus in Lesson 07!

Bevy 0.20 API Highlights
  • Node.border_radius: Rounded corners live right inside Node { border_radius: BorderRadius::all(Val::Px(8.0)), ..default() }.
  • BorderColor::all(color): Because Bevy 0.20 supports individual top/right/bottom/left border colors, use BorderColor::all(...) to color all four sides at once!
  • TextFont::from_font_size(18.0): Converts an f32 pixel height into Bevy 0.20's FontSize::Px(18.0) cleanly via Into<FontSize>.

2. Guided Building Blocks

Step 1

Define HUD Marker Components & spawn_hud

To update specific text labels without touching static containers, tag each dynamic Text entity with its own marker component:

  • #[derive(Component)] pub struct HudTimerText;
  • #[derive(Component)] pub struct HudSurvivorsText;
  • Write spawn_hud(mut commands: Commands) using Bevy's children![...] macro to spawn:
    1. An outer full-width top bar Node at top: Val::Px(10.0) with JustifyContent::Center and Pickable::IGNORE.
    2. An inner pill Node with padding: UiRect::axes(Val::Px(18.0), Val::Px(8.0)), column_gap: Val::Px(22.0), border: UiRect::all(Val::Px(1.0)), border_radius: BorderRadius::all(Val::Px(8.0)), BackgroundColor, and BorderColor::all(...).
    3. Two child Text entities inside the pill—one marked HudTimerText and one marked HudSurvivorsText!
Step 1 Reference Solution 
#[derive(Component)]
pub struct HudTimerText;

#[derive(Component)]
pub struct HudSurvivorsText;

fn spawn_hud(mut commands: Commands) {
    commands.spawn((
        Node {
            position_type: PositionType::Absolute,
            top: Val::Px(10.0),
            left: Val::Px(0.0),
            width: Val::Percent(100.0),
            justify_content: JustifyContent::Center,
            ..default()
        },
        Pickable::IGNORE,
        children![(
            Node {
                padding: UiRect::axes(Val::Px(18.0), Val::Px(8.0)),
                column_gap: Val::Px(22.0),
                align_items: AlignItems::Center,
                border: UiRect::all(Val::Px(1.0)),
                border_radius: BorderRadius::all(Val::Px(8.0)),
                ..default()
            },
            BackgroundColor(Color::srgba(0.08, 0.10, 0.14, 0.92)),
            BorderColor::all(Color::srgb(0.22, 0.28, 0.38)),
            children![
                (
                    HudTimerText,
                    Text::new("IT ELIMINATED IN: 10.0s"),
                    TextFont::from_font_size(18.0),
                    TextColor(Color::srgb(0.92, 0.95, 0.98)),
                ),
                (
                    HudSurvivorsText,
                    Text::new("SURVIVORS: 6"),
                    TextFont::from_font_size(14.0),
                    TextColor(Color::srgb(0.55, 0.62, 0.70)),
                ),
            ],
        )],
    ));
}
Rust Concept: Declarative Macros (children![...])
  • Notice the ! in children![...]! Unlike regular Rust functions (which require every argument to have the exact same type), macros expand at compile time into tuple/relationship code—letting Child 1 and Child 2 have different component tuples while automatically linking them to their parent via Bevy's ChildOf / Children relationship!
  • Also note the parentheses in children![( Node { ... }, ... )] when spawning a single tuple child vs. multiple comma-separated tuple children.
Step 2

Write update_hud in the Update Schedule

Read Res<RoundPhase>, Res<MatchOutcome>, and the count of surviving Character entities to update your two HUD labels every frame:

  • Use timer.remaining_secs() formatted to 1 decimal place: format!("IT ELIMINATED IN: {:.1}s", secs).
  • Turn TextColor urgent coral-red when ActiveTag drops below 3.0s, or warm gold during the 5.0s FlashingNext countdown!
  • Remember: because HudTimerText and HudSurvivorsText both mutate &mut Text, add Without<HudSurvivorsText> / Without<HudTimerText> filters so Bevy knows the two queries never touch the same entity!
Step 2 Reference Solution 
fn update_hud(
    phase: Res<RoundPhase>,
    outcome: Res<MatchOutcome>,
    characters: Query<(), With<Character>>,
    mut timer_q: Query<(&mut Text, &mut TextColor), (With<HudTimerText>, Without<HudSurvivorsText>)>,
    mut surv_q: Query<&mut Text, (With<HudSurvivorsText>, Without<HudTimerText>)>,
) {
    let survivor_count = characters.iter().count();

    for mut text in &mut surv_q {
        text.0 = format!("SURVIVORS: {survivor_count}");
    }

    for (mut text, mut color) in &mut timer_q {
        match *outcome {
            MatchOutcome::PlayerEliminated => {
                text.0 = "GAME OVER — ELIMINATED!".to_string();
                color.0 = Color::srgb(0.97, 0.32, 0.29);
                return;
            }
            MatchOutcome::PlayerWon => {
                text.0 = "VICTORY — YOU SURVIVED!".to_string();
                color.0 = Color::srgb(0.25, 0.85, 0.45);
                return;
            }
            MatchOutcome::Ongoing => {}
        }

        match &*phase {
            RoundPhase::ActiveTag { timer } => {
                let rem = timer.remaining_secs();
                text.0 = format!("IT ELIMINATED IN: {rem:.1}s");
                color.0 = if rem <= 3.0 {
                    Color::srgb(0.98, 0.35, 0.30) // Urgent red!
                } else {
                    Color::srgb(0.92, 0.95, 0.98)
                };
            }
            RoundPhase::FlashingNext { timer, .. } => {
                let rem = timer.remaining_secs();
                text.0 = format!("NEXT IT FLASHING: {rem:.1}s");
                color.0 = Color::srgb(1.0, 0.85, 0.32); // Warning gold!
            }
        }
    }
}

Add spawn_hud to Startup and update_hud to Update:

        .add_systems(Startup, (setup_camera, spawn_arena, spawn_player, spawn_npcs, spawn_hud))
        .add_systems(Update, (sync_character_colors, update_hud))
Rust & Bevy Concepts Inside This Snippet:
  • Disjoint Filters (Without<...>): Why would Bevy panic at startup if you wrote two Query<&mut Text, With<A>> and Query<&mut Text, With<B>> without Without? Because in theory, a single entity could carry both A and B! Adding Without<HudSurvivorsText> proves at the type level that the two queries are 100% disjoint!
  • Zero-Data Query Query<(), With<Character>>: Passing the empty unit tuple () as query data counts matching entities without reading a single byte of component fields!
  • Inline Format Capture (format!("{rem:.1}s")): Modern Rust lets you reference local variables directly inside {...} format braces.
