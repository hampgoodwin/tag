1. Two Classic Bugs Every First Tag Game Hits

Trap #1: The Multi-Tick "Ping-Pong" Tag

Suppose Square A is 'it' and rams into Square B while holding D. On tick 1, your AABB solver separates them by 0.0 px gap and transfers IsIt from A → B. But 15 milliseconds later (tick 2), Square A is still holding D, moving right into B again! Without protection, tick 2 detects another collision and hands IsIt right back from B → A! To a human eye at 64 Hz, who ends up 'it' feels completely random.

The Fix: Attach a brief TagCooldown(Timer) (e.g., 0.45s) whenever a tag occurs so neither participant can immediately re-tag on sustained contact!

Trap #2: Deferred Commands in a 3-Square Pileup

In Bevy ECS, calling commands.entity(old_it).remove::<IsIt>() does not mutate component tables immediately—it queues the change until the end of the system step so active queries stay memory-safe.

Now imagine Square A (IsIt) wedges between Square B and Square C on the exact same physics tick! resolve_character_collisions emits both CollisionMessage(A, B) and CollisionMessage(A, C). If your tag handler checks a read-only Query<..., With<IsIt>>, it still thinks A is 'it' during the second message—spawning two IsIt squares! Even worse, if B and C also collided on that same tick, chaining another transfer immediately would invisibly bounce 'it' A → B → C in 0 ms before TagCooldown has even flushed! Exiting the loop with break; after a single tag transfer per physics tick guarantees at most one clean hand-off per tick and ensures Commands flushes before the next collision check.

2. Decoupling Physics & Gameplay with Bevy 0.20 Messages

Bevy 0.20 Note: Message vs. Event

In Bevy 0.20, buffered inter-system communication uses #[derive(Message)], registered via app.add_message::<CollisionMessage>(), written with MessageWriter<CollisionMessage>, and read with MessageReader<CollisionMessage>! (Event / EntityEvent is now reserved for immediate observer callbacks like UI clicks, which you'll use in Lesson 07.)

Why emit CollisionMessage(Entity, Entity) instead of putting tag rules directly inside resolve_character_collisions? Because your physics solver stays 100% pure geometry & momentum—later you can add sound effects, particle sparks, or camera shake by adding new reader systems without ever touching your AABB math!

// Inside resolve_character_collisions signature:
fn resolve_character_collisions(
    mut query: Query<(Entity, &mut Transform, &mut Velocity, &Collider), With<Character>>,
    mut collisions: MessageWriter<CollisionMessage>,
) {
    let mut combinations = query.iter_combinations_mut();
    while let Some([(entity_a, mut tf_a, mut vel_a, col_a), (entity_b, mut tf_b, mut vel_b, col_b)]) =
        combinations.fetch_next()
    {
        // ... same AABB + MTV + impulse math ...
        if overlap_x > 0.0 && overlap_y > 0.0 {
            // ... separate & apply impulse ...
            collisions.write(CollisionMessage(entity_a, entity_b));
        }
    }
}

fn tick_tag_cooldowns(
    mut commands: Commands,
    time: Res<Time>,
    mut query: Query<(Entity, &mut TagCooldown)>,
) {
    let dt = time.delta();
    for (entity, mut cooldown) in &mut query {
        if cooldown.0.tick(dt).is_finished() {
            commands.entity(entity).remove::<TagCooldown>();
        }
    }
}

fn handle_tag_transfers(
    mut commands: Commands,
    mut collisions: MessageReader<CollisionMessage>,
    it_query: Query<Entity, With<IsIt>>,
    cooldowns: Query<&TagCooldown>,
) {
    let Some(it_entity) = it_query.iter().next() else {
        return;
    };

    for &CollisionMessage(a, b) in collisions.read() {
        // Determine if one of the colliding squares is currently 'it'
        let (old_it, new_it) = if a == it_entity {
            (a, b)
        } else if b == it_entity {
            (b, a)
        } else {
            continue;
        };

        // Ignore if either square is still in post-tag immunity
        if cooldowns.contains(old_it) || cooldowns.contains(new_it) {
            continue;
        }

        commands
            .entity(old_it)
            .remove::<IsIt>()
            .insert(TagCooldown(Timer::from_seconds(TAG_COOLDOWN_SECS, TimerMode::Once)));
        commands.entity(new_it).insert(IsIt);

        // Allow at most one tag transfer per physics tick so deferred Commands
        // flush cleanly before another transfer can occur!
        break;
    }
}
Rust Concepts Inside This Snippet:
  • let ... else Statement: let Some(it_entity) = it_query.iter().next() else { return; }; is modern Rust's cleanest way to unwrap an Option and exit early if nobody is currently 'it'—zero rightward indentation drift!
  • Destructuring in Loop Header: for &CollisionMessage(a, b) in collisions.read() copies the two Entity IDs right out of the borrowed message reference.
Step 3

Upgrade npc_steering (Chase Nearest / Flee 'It') & Sync Colors

Now bring the arena to life!

  • In npc_steering, include Option<&IsIt> in all_characters snapshot: Vec<(Entity, Vec2, bool)>.
    • If this NPC is 'it': Find the closest other character using .min_by(|a, b| dist_a.total_cmp(&dist_b)) and steer straight toward them! (Skip wall avoidance when chasing closely so 'it' can corner victims against walls!)
    • If this NPC is NOT 'it': Steer away from the 'it' character's position + keep your personal-space separation and soft wall avoidance so fleeing NPCs curve around corners instead of trapping themselves!
  • Write sync_character_colors in Update querying (&mut Sprite, Option<&Player>, Option<&IsIt>), With<Character>:
    • IsIt → bright coral-red Color::srgb(0.97, 0.32, 0.29) (even if it's the Player, maybe slightly brighter orange-red so you always know who is 'it'!).
    • Player (safe) → sky blue Color::srgb(0.30, 0.67, 0.97).
    • Npc (safe) → mint green Color::srgb(0.41, 0.86, 0.49).
Step 3 Reference Solution 
fn npc_steering(
    time: Res<Time>,
    arena: Res<ArenaBounds>,
    all_characters: Query<(Entity, &Transform, Option<&IsIt>), With<Character>>,
    mut npcs: Query<(Entity, &Transform, &MoveSpeed, &mut Velocity, Option<&IsIt>), With<Npc>>,
) {
    let snapshot: Vec<(Entity, Vec2, bool)> = all_characters
        .iter()
        .map(|(e, tf, is_it)| (e, tf.translation.truncate(), is_it.is_some()))
        .collect();

    let it_pos = snapshot
        .iter()
        .find(|&&(_, _, is_it)| is_it)
        .map(|&(_, pos, _)| pos);

    let dt = time.delta_secs();
    let blend = (NPC_STEER_ACCEL * dt).min(1.0);
    let wall_margin = 85.0;

    for (entity, transform, speed, mut velocity, is_it) in &mut npcs {
        let pos = transform.translation.truncate();
        let mut steer = Vec2::ZERO;

        if is_it.is_some() {
            // CHASE: head directly toward the closest non-self character
            if let Some(&(_, target_pos, _)) = snapshot
                .iter()
                .filter(|&&(other_e, _, _)| other_e != entity)
                .min_by(|&&(_, pos_a, _), &&(_, pos_b, _)| {
                    pos.distance_squared(pos_a)
                        .total_cmp(&pos.distance_squared(pos_b))
                })
            {
                steer = (target_pos - pos).normalize_or_zero();
            }
        } else {
            // FLEE: steer away from 'it' (capped below wall repulsion so NPCs curve out of corners!)
            if let Some(threat_pos) = it_pos {
                let away = pos - threat_pos;
                let dist = away.length().max(1.0);
                let urgency = (280.0 / dist).clamp(0.8, 2.2);
                steer += (away / dist) * urgency;
            } else {
                steer += velocity.0.normalize_or(Vec2::X);
            }

            // Personal-space separation from fellow runners
            for &(other_e, other_pos, _) in &snapshot {
                if other_e == entity {
                    continue;
                }
                let away = pos - other_pos;
                let dist = away.length();
                if dist > 0.001 && dist < 85.0 {
                    steer += (away / dist) * ((85.0 - dist) / 85.0) * 1.2;
                }
            }

            // Soft wall avoidance so runners bank along edges instead of pinning into corners
            let dist_right = arena.half_size.x - pos.x;
            let dist_left = arena.half_size.x + pos.x;
            let dist_top = arena.half_size.y - pos.y;
            let dist_bottom = arena.half_size.y + pos.y;

            if dist_right < wall_margin {
                steer.x -= ((wall_margin - dist_right) / wall_margin) * 2.6;
            }
            if dist_left < wall_margin {
                steer.x += ((wall_margin - dist_left) / wall_margin) * 2.6;
            }
            if dist_top < wall_margin {
                steer.y -= ((wall_margin - dist_top) / wall_margin) * 2.6;
            }
            if dist_bottom < wall_margin {
                steer.y += ((wall_margin - dist_bottom) / wall_margin) * 2.6;
            }
        }

        let desired_vel = steer.normalize_or_zero() * speed.0;
        velocity.0 = velocity.0.lerp(desired_vel, blend);
    }
}

fn sync_character_colors(
    mut query: Query<(&mut Sprite, Option<&Player>, Option<&IsIt>), With<Character>>,
) {
    for (mut sprite, player, is_it) in &mut query {
        sprite.color = match (is_it.is_some(), player.is_some()) {
            (true, true) => Color::srgb(1.0, 0.45, 0.20),   // Player is IT (vivid orange-red)
            (true, false) => Color::srgb(0.95, 0.26, 0.26),  // NPC is IT (crimson red)
            (false, true) => Color::srgb(0.30, 0.67, 0.97),  // Player safe (sky blue)
            (false, false) => Color::srgb(0.41, 0.86, 0.49), // NPC safe (mint green)
        };
    }
}

Rust Concepts Inside This Snippet:
  • Why distance_squared + total_cmp? Comparing squared distances avoids calling expensive square-root instructions in a loop (a < b iff a² < b² for non-negative numbers!). And because IEEE-754 floats can represent NaN, Rust's f32 only implements PartialOrd, not Ord—so .min_by() uses f32::total_cmp(&other) to provide a total ordering!
  • Exhaustive Tuple Matching: match (is_it.is_some(), player.is_some()) matches a (bool, bool) pair. Rust's compiler statically proves all 4 combinations are covered!
