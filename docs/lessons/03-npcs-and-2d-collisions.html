1. AABB Collision Detection & Minimum Translation Vector (MTV)

Because our squares never rotate, their sides stay aligned with the world X and Y axes. That makes each square an Axis-Aligned Bounding Box (AABB) defined by its center pos and half_size.

Given Square A at pos_a (half-size h_a) and Square B at pos_b (half-size h_b), let delta = pos_b - pos_a:

  • X-axis penetration: overlap_x = (h_a.x + h_b.x) - delta.x.abs()
  • Y-axis penetration: overlap_y = (h_a.y + h_b.y) - delta.y.abs()

Two AABBs collide if and only if both overlap_x > 0.0 AND overlap_y > 0.0! If there is a gap on either axis, they are not touching.

Step A of Resolution: Positional Separation Along the MTV

When overlap_x > 0.0 && overlap_y > 0.0, which way should we push the squares apart? Always choose the axis with the smaller overlap! Think about running into the side of a wide wall: overlap_x might be 2.0 px while overlap_y is 26.0 px—you clearly hit it horizontally, not vertically!

  • Let unit normal normal point from A toward B along that minimum axis (e.g., if overlap_x < overlap_y, normal = Vec2::new(if delta.x >= 0.0 { 1.0 } else { -1.0 }, 0.0) and penetration = overlap_x).
  • Push A and B apart equally: pos_a -= normal * (penetration * 0.5) and pos_b += normal * (penetration * 0.5).

Step B of Resolution: Elastic Velocity Impulse

Separating positions stops overlap, but their velocities are still pointing into each other! To make them bounce realistically:

  1. Compute relative velocity of B with respect to A: rel_vel = vel_b - vel_a.
  2. Project onto the collision normal using the dot product: vel_along_normal = rel_vel.dot(normal).
  3. Crucial guard: If vel_along_normal >= 0.0, the squares are already moving apart—do not apply an impulse!
  4. For two equal-mass squares with restitution (bounciness) RESTITUTION = 0.85: 
    let impulse_mag = -(1.0 + RESTITUTION) * vel_along_normal * 0.5;
let impulse = normal * impulse_mag;
vel_a -= impulse;
vel_b += impulse;

2. Simple Steering Velocity for NPCs

Instead of moving like mindless billiard balls, NPCs use Reynolds Steering: each tick, an NPC computes a desired_dir: Vec2, scales it by MoveSpeed (1.0 × BASE_SPEED = 220.0 px/s, slower than your 264.0 px/s player!), and smoothly turns its current Velocity toward that goal.

In this lesson (before we introduce 'it' in Lesson 04), each NPC combines three simple steering desires:

  • Cruise forward: Keep heading along its current direction (or a gentle initial heading if nearly stopped) so NPCs roam actively across the open area.
  • Personal-space separation: Gently steer away from any neighbor within 95 px so NPCs spread out across the arena instead of clumping.
  • Soft wall avoidance: Within 75 px of any arena wall, add an inward push proportional to how close the wall is, so NPCs bank smoothly away from corners!

In Lesson 04, adding full Chase (when 'it') & Flee (when not 'it') behavior will simply add one vector to this exact steering sum!

3. Guided Building Blocks

Step 1

Add Npc Marker & Spawn 5 NPC Squares

Define NPC_COUNT: usize = 5, NPC_STEER_ACCEL: f32 = 6.0, RESTITUTION: f32 = 0.85, and a unit component Npc. Then write a spawn_npcs(mut commands: Commands) startup system that spawns 5 green/teal squares arranged in a ring around the player (so nobody starts overlapping at (0, 0)!):

  • Use angle angle = (i as f32 / NPC_COUNT as f32) * std::f32::consts::TAU (TAU = 2π, a full circle!).
  • Position on a ring of radius 180.0: pos = Vec2::from_angle(angle) * 180.0.
  • Give each NPC an initial Velocity(Vec2::from_angle(angle + 1.2) * BASE_SPEED), MoveSpeed(BASE_SPEED) (1.0× speed!), Character, Npc, and Collider.
Step 1 Reference Solution 
pub const NPC_COUNT: usize = 5;
pub const NPC_STEER_ACCEL: f32 = 6.0;
pub const RESTITUTION: f32 = 0.85;

#[derive(Component)]
pub struct Npc;

fn spawn_npcs(mut commands: Commands) {
    let npc_color = Color::srgb(0.41, 0.86, 0.49);

    for i in 0..NPC_COUNT {
        let angle = (i as f32 / NPC_COUNT as f32) * std::f32::consts::TAU;
        let pos = Vec2::from_angle(angle) * 180.0;
        let initial_dir = Vec2::from_angle(angle + 1.2);

        commands.spawn((
            Character,
            Npc,
            Sprite::from_color(npc_color, Vec2::splat(CHARACTER_SIZE)),
            Transform::from_xyz(pos.x, pos.y, 2.0),
            Velocity(initial_dir * BASE_SPEED),
            MoveSpeed(BASE_SPEED),
            Collider {
                half_size: Vec2::splat(CHARACTER_SIZE * 0.5),
            },
        ));
    }
}
Rust Concepts Inside This Snippet:
  • Explicit Numeric Casting (i as f32): Loop range 0..NPC_COUNT yields usize integers. Rust requires explicit as f32 casts so accidental integer division (where 1 / 5 == 0!) can never silently zero out your angles!
  • Vec2::from_angle(radians): Returns the unit vector (cos(θ), sin(θ)) directly.
Step 2

Implement npc_steering

Write npc_steering to steer every Npc smoothly at 1.0 × BASE_SPEED. Wait—how can an NPC read the positions of all characters while mutating its own Velocity without violating Rust's borrow checker?

Cleanest Rust pattern: Use two non-conflicting queries—all_characters: Query<(Entity, &Transform), With<Character>> (read-only) and mut npcs: Query<(Entity, &Transform, &MoveSpeed, &mut Velocity), With<Npc>>—collect a tiny Vec<(Entity, Vec2)> snapshot in pass 1, then compute steering vectors in pass 2! With 6 characters, collecting a 6-element Vec takes nanoseconds and keeps the math super readable—especially in Lesson 04 when NPCs inspect who IsIt!

Step 2 Reference Solution 
fn npc_steering(
    time: Res<Time>,
    arena: Res<ArenaBounds>,
    all_characters: Query<(Entity, &Transform), With<Character>>,
    mut npcs: Query<(Entity, &Transform, &MoveSpeed, &mut Velocity), With<Npc>>,
) {
    let snapshot: Vec<(Entity, Vec2)> = all_characters
        .iter()
        .map(|(e, tf)| (e, tf.translation.truncate()))
        .collect();

    let dt = time.delta_secs();
    let blend = (NPC_STEER_ACCEL * dt).min(1.0);
    let wall_margin = 75.0;

    for (entity, transform, speed, mut velocity) in &mut npcs {
        let pos = transform.translation.truncate();

        // 1. Keep cruising along current heading (fallback if nearly zero)
        let mut steer = velocity.0.normalize_or(Vec2::X);

        // 2. Gentle personal-space separation from nearby characters
        for &(other_entity, other_pos) in &snapshot {
            if other_entity == entity {
                continue;
            }
            let away = pos - other_pos;
            let dist = away.length();
            if dist > 0.001 && dist < 95.0 {
                steer += (away / dist) * ((95.0 - dist) / 95.0) * 1.4;
            }
        }

        // 3. Soft wall-margin avoidance so NPCs curve smoothly inside the arena
        let dist_right = arena.half_size.x - pos.x;
        let dist_left = arena.half_size.x + pos.x;
        let dist_top = arena.half_size.y - pos.y;
        let dist_bottom = arena.half_size.y + pos.y;

        if dist_right < wall_margin {
            steer.x -= ((wall_margin - dist_right) / wall_margin) * 2.2;
        }
        if dist_left < wall_margin {
            steer.x += ((wall_margin - dist_left) / wall_margin) * 2.2;
        }
        if dist_top < wall_margin {
            steer.y -= ((wall_margin - dist_top) / wall_margin) * 2.2;
        }
        if dist_bottom < wall_margin {
            steer.y += ((wall_margin - dist_bottom) / wall_margin) * 2.2;
        }

        let desired_vel = steer.normalize_or_zero() * speed.0;
        velocity.0 = velocity.0.lerp(desired_vel, blend);
    }
}
Rust & Bevy Borrow-Checker Insight:
  • Notice that all_characters only borrows &Transform (shared/immutable), while npcs borrows &Transform, &MoveSpeed, and &mut Velocity! Because neither query mutates Transform, and only npcs touches Velocity, Bevy verifies at startup that these two queries have zero mutable aliasing conflict!
  • tf.translation.truncate() drops the z coordinate of a Vec3 to give you a 2D Vec2.
Step 3

Implement resolve_character_collisions (AABB + MTV + Bounce)

Now write the pairwise AABB collision system over mut query: Query<(&mut Transform, &mut Velocity, &Collider), With<Character>>!

Rust Deep Dive: Why iter_combinations_mut() Uses fetch_next()

If you tried writing nested loops for a in &mut query { for b in &mut query { ... } }, Rust would immediately reject your code: when a == b, you would hold two mutable references to the exact same memory (instant Undefined Behavior in Rust!).

Even more subtly: why can't query.iter_combinations_mut() use a normal for [a, b] in ... loop? Because Rust's standard Iterator::next trait allows callers to call .collect::<Vec<_>>(), which would hold [&mut A, &mut B] and [&mut A, &mut C] alive at the same time—aliasing &mut A! Instead, Bevy returns a lending iterator whose .fetch_next() method ties the lifetime of [a, b] to the loop body: 

let mut combinations = query.iter_combinations_mut();
while let Some([mut a, mut b]) = combinations.fetch_next() {
    // Guaranteed: `a` and `b` are two DIFFERENT entities, and dropped before next iteration!
}
Step 3 Reference Solution 
fn resolve_character_collisions(
    mut query: Query<(&mut Transform, &mut Velocity, &Collider), With<Character>>,
) {
    let mut combinations = query.iter_combinations_mut();

    while let Some([(mut tf_a, mut vel_a, col_a), (mut tf_b, mut vel_b, col_b)]) =
        combinations.fetch_next()
    {
        let pos_a = tf_a.translation.truncate();
        let pos_b = tf_b.translation.truncate();
        let delta = pos_b - pos_a;

        let overlap_x = (col_a.half_size.x + col_b.half_size.x) - delta.x.abs();
        let overlap_y = (col_a.half_size.y + col_b.half_size.y) - delta.y.abs();

        if overlap_x > 0.0 && overlap_y > 0.0 {
            // 1. Minimum Translation Vector (axis of least penetration, pointing A -> B)
            let (normal, penetration) = if overlap_x < overlap_y {
                let sign = if delta.x >= 0.0 { 1.0 } else { -1.0 };
                (Vec2::new(sign, 0.0), overlap_x)
            } else {
                let sign = if delta.y >= 0.0 { 1.0 } else { -1.0 };
                (Vec2::new(0.0, sign), overlap_y)
            };

            // 2. Separate positions 50% / 50% so they no longer overlap
            let correction = normal * (penetration * 0.5);
            tf_a.translation.x -= correction.x;
            tf_a.translation.y -= correction.y;
            tf_b.translation.x += correction.x;
            tf_b.translation.y += correction.y;

            // 3. Apply elastic impulse if approaching along normal
            let rel_vel = vel_b.0 - vel_a.0;
            let vel_along_normal = rel_vel.dot(normal);

            if vel_along_normal < 0.0 {
                let impulse = normal * (-(1.0 + RESTITUTION) * vel_along_normal * 0.5);
                vel_a.0 -= impulse;
                vel_b.0 += impulse;
            }
        }
    }
}

Wire spawn_npcs into Startup and update your FixedUpdate chain so collisions resolve after movement and before confine_to_arena:

        .add_systems(Startup, (setup_camera, spawn_arena, spawn_player, spawn_npcs))
        .add_systems(
            FixedUpdate,
            (
                player_input,
                npc_steering,

            )
                .chain(),

Why Run confine_to_arena Last?
  • If two squares collide right next to a border wall, resolve_character_collisions pushes each square outward by penetration * 0.5. Running confine_to_arena immediately afterward guarantees that separation push can never shove a square outside the arena walls!
  • Notice let (normal, penetration) = if overlap_x < overlap_y { ... } else { ... };—in Rust, if / else is an expression that returns a value, letting you initialize normal and penetration immutably in one clean step!
