1. How Bevy Measures 2D Space

In web browsers and many older 2D APIs, (0, 0) is the top-left pixel and +Y points downward. Bevy uses standard mathematical Cartesian coordinates because its 2D and 3D math share the same unified Transform system:

  • When you spawn a default Camera2d, it looks straight at world origin (0.0, 0.0) in the exact center of the window.
  • +X points right; -X points left.
  • +Y points up; -Y points down.
  • +Z points toward the camera—higher z values draw on top of lower z values (e.g., arena floor at z = 0.0, walls at z = 1.0, characters at z = 2.0).
Physics Pro-Tip: Store Half-Sizes (Half-Extents)

Every Sprite in Bevy is positioned by its center by default. If your open arena is 800 × 560 logical pixels centered at (0, 0), then its playable interior spans x ∈ [-400, +400] and y ∈ [-280, +280]. Storing ArenaBounds { half_size: Vec2::new(400.0, 280.0) } keeps the room's geometry cleanly separated from the entities inside it—and turns every physics formula into simple add/subtract of half-sizes:

  • Wall placement (this lesson): arena.half_size + wall_half_thickness
  • Edge-to-wall player clamping (Lesson 02): arena.half_size - collider.half_size — for a 28 × 28 player (half_size = 14), the player's center stays inside (±386, ±266) so its outer edge stops flush at (±400, ±280)!
  • Square-vs-square AABB overlap (Lesson 03): (col_a.half_size + col_b.half_size) - delta.abs()

2. Bevy 0.20 Required Components (No More *Bundle Boilerplate)

If you search online for older Bevy tutorials (0.14 and earlier), you will see code like Camera2dBundle::default() and SpriteBundle { ... }. In Bevy 0.20, components declare their own dependencies automatically using Required Components:

  • Spawning Camera2d automatically inserts Camera, Transform, Projection (configured with OrthographicProjection::default_2d()), and Visibility with sensible defaults.
  • Spawning Sprite::from_color(color, size) automatically inserts Transform::default() (at (0, 0, 0)) and Visibility::default()—unless you explicitly include your own Transform alongside it in the tuple!
Rust Concept: Tuple Bundles & Trait Implementations

How can commands.spawn(...) accept a single struct like Camera2d or a 2-tuple (Sprite, Transform) or a 5-tuple? In Rust, a tuple (A, B, C) is a distinct type from A. Bevy implements its Bundle trait for every Component and for tuples of bundles up to 15 elements! Each element in the tuple becomes a component attached to the same newly spawned Entity.

3. Guided Building Blocks

Open src/main.rs. You can clear out HelloPlugin, Person, Name, and GreetTimer—we are building our Tag game from here!

Step 1

Define Arena Constants, ArenaBounds Resource & Wall Marker

Start by defining compile-time constants for your arena dimensions and two ECS types:

  • Constants: ARENA_WIDTH: f32 = 800.0, ARENA_HEIGHT: f32 = 560.0, and WALL_THICKNESS: f32 = 16.0.
  • A resource struct ArenaBounds with field pub half_size: Vec2. Derive Resource, Clone, Copy, Debug.
  • A unit marker component Wall deriving Component (we'll attach this to wall entities so future obstacle maps work seamlessly!).
Step 1 Reference Solution 
use bevy::prelude::*;

pub const ARENA_WIDTH: f32 = 800.0;
pub const ARENA_HEIGHT: f32 = 560.0;
pub const WALL_THICKNESS: f32 = 16.0;

#[derive(Resource, Clone, Copy, Debug)]
pub struct ArenaBounds {
    pub half_size: Vec2,
}

#[derive(Component)]
pub struct Wall;
Rust Concepts Inside This Snippet:
  • const values are inlined directly at compile time and must have an explicit type annotation (like : f32). Note the .0 on floats—Rust never implicitly converts integers like 800 into f32!
  • #[derive(Clone, Copy)] on ArenaBounds tells Rust that copying two 32-bit floats (8 bytes total) is trivial bitwise copying, so passing arena.half_size around won't "move" ownership out of the struct.
  • pub struct Wall; is a Zero-Sized Type (ZST)—it takes 0 bytes of RAM at runtime while letting Bevy filter entities with With<Wall>!
Step 2

Write the setup_camera & spawn_arena Startup Systems

Create a startup system (or two small startup systems) using Commands and Res<ArenaBounds>:

  • Spawn Camera2d so Bevy renders 2D sprites centered at (0, 0).
  • Spawn a dark-slate floor rectangle at Transform::from_xyz(0.0, 0.0, 0.0) using Sprite::from_color(Color::srgb(0.11, 0.14, 0.19), arena.half_size * 2.0).
  • Spawn 4 boundary wall entities (Top, Bottom, Left, Right) at z = 1.0, each with the Wall component, a contrasting Sprite::from_color, and a Transform::from_xyz(...) placed just outside arena.half_size:
    • Top/Bottom walls: width ARENA_WIDTH + WALL_THICKNESS * 2.0 (so the corners cap cleanly!), height WALL_THICKNESS, at y = ±(arena.half_size.y + WALL_THICKNESS * 0.5).
    • Left/Right walls: width WALL_THICKNESS, height ARENA_HEIGHT, at x = ±(arena.half_size.x + WALL_THICKNESS * 0.5).
Step 2 Reference Solution 
fn setup_camera(mut commands: Commands) {
    commands.spawn(Camera2d);
}

fn spawn_arena(mut commands: Commands, arena: Res<ArenaBounds>) {
    let full_size = arena.half_size * 2.0;
    let wall_color = Color::srgb(0.28, 0.34, 0.45);

    // 1. Open arena floor (z = 0.0)
    commands.spawn((
        Sprite::from_color(Color::srgb(0.11, 0.14, 0.19), full_size),
        Transform::from_xyz(0.0, 0.0, 0.0),
    ));

    // 2. Four perimeter walls (z = 1.0)
    let half_w = arena.half_size.x;
    let half_h = arena.half_size.y;
    let half_t = WALL_THICKNESS * 0.5;

    let walls = [
        // (center_x, center_y, width, height)
        (0.0, half_h + half_t, full_size.x + WALL_THICKNESS * 2.0, WALL_THICKNESS), // Top
        (0.0, -(half_h + half_t), full_size.x + WALL_THICKNESS * 2.0, WALL_THICKNESS), // Bottom
        (-(half_w + half_t), 0.0, WALL_THICKNESS, full_size.y), // Left
        (half_w + half_t, 0.0, WALL_THICKNESS, full_size.y),  // Right
    ];

    for (x, y, w, h) in walls {
        commands.spawn((
            Wall,
            Sprite::from_color(wall_color, Vec2::new(w, h)),
            Transform::from_xyz(x, y, 1.0),
        ));
    }
}
Rust Concepts Inside This Snippet:
  • Operator Overloading (arena.half_size * 2.0): Vec2 implements Rust's std::ops::Mul<f32> trait, multiplying both x and y cleanly.
  • Array + Tuple Destructuring: walls is a stack-allocated fixed-size array [(f32, f32, f32, f32); 4]. Writing for (x, y, w, h) in walls unpacks each 4-tuple right in the loop header!
  • Shared Borrow via Res<ArenaBounds>: Notice arena is not mut because this system only reads the arena dimensions, allowing Bevy's scheduler to run other read-only systems in parallel.
Step 3

Wire Up App::new() in main()

Configure your Bevy App in fn main():

  • Add DefaultPlugins (optionally customize WindowPlugin so the window title says "Tag" and fits your arena with comfortable margin, e.g., 1000 × 720).
  • Insert ClearColor(Color::srgb(0.05, 0.07, 0.10)) for the backdrop outside the walls.
  • Insert ArenaBounds { half_size: Vec2::new(ARENA_WIDTH * 0.5, ARENA_HEIGHT * 0.5) }.
  • Register (setup_camera, spawn_arena) on the Startup schedule and call .run().
Step 3 Reference Solution 
fn main() {
    App::new()
        .add_plugins(DefaultPlugins.set(WindowPlugin {
            primary_window: Some(Window {
                title: "Tag".into(),
                resolution: (1000, 720).into(),
                ..default()
            }),
            ..default()
        }))
        .insert_resource(ClearColor(Color::srgb(0.05, 0.07, 0.10)))
        .insert_resource(ArenaBounds {
            half_size: Vec2::new(ARENA_WIDTH * 0.5, ARENA_HEIGHT * 0.5),
        })
        .add_systems(Startup, (setup_camera, spawn_arena))
        .run();
}
Rust Concepts Inside This Snippet:
  • Struct Update Syntax (..default()): Window has dozens of configuration fields (cursor options, vsync, mode, etc.). Writing ..default() fills every unspecified field from Window::default()!
  • .into() Type Conversion: "Tag" has type &'static str, while Window.title expects an owned String. Calling .into() invokes Rust's Into<String> trait inferred from the struct field's type!
